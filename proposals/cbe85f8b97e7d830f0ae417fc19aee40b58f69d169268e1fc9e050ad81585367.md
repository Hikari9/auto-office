## Proposed diff

Make the adapter fingerprint the source of truth for candidate identity and make observation
mandatory before any route, trust act, or outcome label is recorded:

```yaml
version_fingerprint:
  command: [codex, --version]
  parser: first-line-semver
  required_for_candidate_identity: true
```

The adapter resolver should execute that command once per adapter-resolution context, normalize
the semver from the first line, and pass the observed value into candidate construction. A
candidate must be rejected before routing if the command is unavailable, unparsable, or the
supplied `harness_version` differs from the observed value. It must never guess, silently
substitute a configured version, or rewrite an old evidence row. For this observation,
`codex-cli 0.154.0` becomes `0.154.0` and `0.58.0` is stale/unobserved.

The static adapter file should declare the requirement and normalization rule, not pin a
machine-specific version. Existing evidence keeps its original identity and is not relabeled
retroactively.
