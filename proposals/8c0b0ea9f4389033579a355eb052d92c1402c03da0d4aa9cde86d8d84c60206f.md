## Proposed diff

Choose the `preferred_rank`/invocation-identity correction, implemented as a catalog-aware
match rather than a string heuristic:

```text
Before: preferred.model_id == candidate.model_id
After:  resolve preferred.model_id through catalog rows, expand the identity with the
        row's invocation_model_id and invocation_harness, then match candidate.model_id or
        candidate.invocation_model_id while retaining effort and optional harness checks
```

The resolution must be explicit and fail closed on an ambiguous harness mapping. It must not
infer aliases from suffixes, rename any `model_id`, or mark the identity-only normative row
dispatchable merely to make the rank appear to work. This preserves canonical spec names while
allowing `luna -> gpt-5.6-luna`, `opus -> claude-opus-5`, and `astra -> gpt-6-astra` to bind when
the corresponding dispatch identity is actually available.
