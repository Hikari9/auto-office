# Codex pane and ledger traps (observed 2026-09-27)
- Never send `esc` (or any key) to a codex pane to scroll or "wake" it: codex treats `esc` as interrupt and aborts the in-flight turn. `agent wait` has also reported `done` while codex was still mid-turn. Read output with `agent read --source recent-unwrapped` only once `agent get` shows the agent settled, and confirm the reply is actually complete (a final verdict line, the composer prompt back) before acting on it.
- A codex dispatch launched with `-s read-only` cannot write a result file (Office now takes a read-only reviewer's reply from its transcript; see "Observed 2026-09-30" below) and cannot run `pnpm`/`vitest` (Corepack fails with EPERM writing a `package.json` in the home directory). Brief a read-only reviewer to answer in chat, and have the orchestrator run the tests itself and pass the results in.
- `close_finished_panes.mjs` closes a pane only when a trusted terminal completion event exists for the ledger row's `dispatch_id` (`scripts/office_monitor.py`, source `monitor_bridge` or `process_exit`). A row added by hand with `herdr-ledger.mjs add` and no `--dispatch` has `dispatch_id: null`, so the sweep keeps it open forever, even when it is marked `done`/`closeable`. Either pass `--dispatch <id>` and record completion through `office_monitor.py`, or close your own finished pane explicitly with `herdr pane close <pane-id>` after verifying its result, then mark the row `closed`.

# Observed 2026-09-30: codex folder-trust dialog eats the brief
- Interactive codex started in a directory it has not trusted (every new Office dispatch dir or review checkout) opens on "Trust this folder? 1. Trust and continue / 2. Quit". `agent prompt` still returns success and `agent list` can read `working`, but the pointer never reaches the composer. The reviewer later exits with no reply and the gate goes UNAVAILABLE. Office's codex interactive argv now pre-trusts its cwd for that session only: `-c 'projects={"<resolved cwd>"={trust_level="trusted"}}'`. The dotted `projects."<path>".trust_level` form does not work on codex 0.159, and the inline form writes nothing to `~/.codex/config.toml`. When starting codex by hand, pass that flag, or `herdr pane read` first and answer the dialog with Enter before prompting.
- Judge "landed" by the pane or the transcript, never by `agent_status`. Valid signals are a busy footer (`esc to interrupt`), the Claude status line `ctx:` rising above its pre-prompt value (a narrow pane never shows the footer), or the harness transcript logging the pointer as a user prompt. Codex sometimes needs a second Enter.
- Wait for `herdr pane get <pane>` to report the agent before sending anything. `herdr pane run <pane> "<pointer>"` sent before the agent is up types into the bare shell. Send the pointer with `herdr agent prompt`.
- A read-only external reviewer cannot write `reply.txt`. Office's pointer tells it to end its reply with the review instead, and the external watcher takes that reply from the harness transcript once it holds a `VERDICT:` line.
- For a submitted task blocked only by an UNAVAILABLE code review, `office dispatch <T> [--review-as ...]` re-runs just that review on the same revision. It launches no executor unless `--as`, `--route`, `--cli` or `--external` asks for one.
