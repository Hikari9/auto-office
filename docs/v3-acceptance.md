# Auto Office v3 — Acceptance Matrix

## Overview and Status

This document defines the authoritative, machine-checkable acceptance matrix for Auto Office v3. It enumerates all requirements across the three governing issues:
- Issue #35: Wayfinder: adaptive harness/model routing (including child decisions #44–#59, #72, #81–#85, and confirmed decisions 1–8); see `gh issue view 35` in the project repository.
- Issue #77: Interactive planner families and multi-project orchestrator control plane (including compaction addendum); see `gh issue view 77`.
- Issue #93: Auto Office v3 orchestrator portability (including withdrawal of approval-hook enforcement); see `gh issue view 93`.
- Accepted material findings from the independent plan review recorded in `docs/plans/v3-final-merge.md`;
- And amendment-v3 requirements for derived trust, capability floors, outcome labels, and local rewards (Task T2B).

Per the plan specification (amendment v2 finding F13, amendment v3), every requirement is an individual falsifiable row carrying:
1. **Source & Decision ID** (e.g. `issue-35#decision-5`)
2. **Behavior** (one falsifiable sentence)
3. **Owning Task ID** (T0–T8, T2B, T5S)
4. **Pointer** (`path:line` in implementation or specification)
5. **Verification Command** (exact checkable command or live observation)
6. **Evidence Path or Hash**
7. **Status** (`verified | missing | conflict | external-blocker | superseded`)
8. **Disposition** (explicit approval citation for `superseded`, or blocker disposition for `external-blocker`)

would break at least one assertion if the behaviour were removed. A row is `missing` when the
command fails and the behaviour is absent. Everything else is `conflict`.

Two rows outside this pass, `issue-35#decision-8` and `issue-93#portability-demonstration`,
remain `verified` with dispositions stating that a file-existence check plus a privacy linter
cannot distinguish a genuine transcript from a fabricated one. By the rule above they are
`conflict`. They were left untouched because they were not among the 70 rows in scope.

A row is `verified` here only when someone ran the command in its Verification column, recorded
the output, and that output could not have been produced with the behaviour absent.
