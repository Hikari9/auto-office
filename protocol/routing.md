# Routing

Route identity is `harness@version × model_id × effort`. Public benchmark identity is only `model_id × effort`; never share runtime reliability, quota, dispatch-form, or adapter-trust evidence automatically across harnesses.

Filter in this exact order: hard exclusions → adapter validity/trust → required capabilities → absolute role floor → task shape → quota safety → advisory quality anchor → cost → local tie-break evidence.

**Each filter's input is derived, not caller-supplied (amendment v3, narrowed by v5/v6).** A candidate asserting its own `adapter_state`, `absolute_floor_pass`, or `local_reward` is routed exactly as if it had asserted nothing — `route()` ignores those fields and recomputes them:

- **Adapter validity/trust.** A query may **lower** adapter trust and may **never raise it**. An unresolved adapter-attributed critical failure quarantines a triple automatically, from recorded dispatch/outcome-label evidence, with no human action. The floor absent any explicit act is `valid-unverified`, never `proven`, no matter how many successful dispatches accumulated — `adapter_trust.proven_min_successful_dispatches`/`proven_min_task_shapes` are advisory reference numbers an operator may consult, not a threshold any query evaluates; nothing in the runtime reads them automatically, and that is by design, not a gap. Every upward transition (`quarantined` → `valid-unverified`, anything → `proven`) is an explicit recorded trust act carrying its own `actor_id`, never inferred, backfilled, or computed from a dispatch count or label. See `protocol/adapters.md`.
- **Absolute role floor.** Evaluated against the candidate's pinned catalog row and the declared `roles.<role>.floor` in `config/config.default.yaml`. When a catalog field the floor needs is unknown, the floor fails closed and names the missing field; unknown never passes.
- **Local tie-break evidence.** Derived from labeled outcome rows for the exact routable triple and task shape. Absent labels, the reward is unknown (`None`) and contributes nothing — it is never treated as a measured zero.

**The recorded-override path is the only way past a derived gate.** An explicit override of adapter trust, the absolute floor, or the advisory anchor is honoured only when a `RecordedOverride` exists carrying user attribution (`authorized_by: "user"`), the scope it covers, and an unexpired `expires_at`, and it then surfaces in `selection_disclosure`. A request that asserts `allow_unverified_override`/`allow_override` without a valid, unexpired recorded authorization is a hard stop (`status: "override_not_authorized"`), not a softer warning. The normative artifact for the adapter-trust properties above is `tests/test_trust_conformance.py`, not this document or any SQL example — see `docs/v3-runtime-contracts.md` §7 for the full contract T2B implements against.

Quota reserve defaults to 20%. Unknown quota is not unlimited. Exclude a candidate whose projected dispatch crosses reserve when another qualifying candidate exists. If all qualifying candidates cross reserve, return to the orchestrator for a smaller valid strategy, lower-cost route, or explicit user decision; do not lower capability floors.

Balanced cost policy: eliminate quota-unsafe; estimate money; among candidates within 20% of the cheapest money estimate prefer lower quota burn; then lower wall clock; then stronger local reward. Support `money_saver`, `quota_saver`, `balanced`.

Advisory quality anchor: when the resolved role config has a `preferred_seed` (an ordered `{model_id, effort, harness?}` chain), it drives the anchor directly. A candidate matching an entry passes; with no match the anchor imposes no restriction. Passing candidates are then ordered by chain position before cost — the first entry wins whenever it clears every earlier stage, with cost/quota/wall/reward only breaking ties within the same chain position. This intentionally overrides the balanced money-band elimination for the chain's own entries, since the chain already encodes the user's explicit cost/quality tradeoff.

Exploration is limited to workers, Investigate/Prototype, reversible sandbox, non-production. Default maximum one exploratory dispatch/run, max 10% over rolling 20 eligible workers, and <=125% of cheapest qualifying projected cost without explicit user approval.

Every successful route emits `selection_disclosure`: role, canonical `model_id`, exact `invocation_model_id` when exposed by the harness binding, effort, harness/version, selected triple, and a concise reason derived from the decisive filter/tie-break evidence. This object is durable handoff data. Executor and reviewer dispatches surface it to the user immediately before invocation and preserve it in dispatch/readback evidence.
